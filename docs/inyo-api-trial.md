# 逆リンクのAPI試用（2026-10-30）

同梱JSON・インポート済み逆リンクを参照せず、e-Gov内部APIで外部引用元を取得する試用実装。法令内の逆リンク解析は従来どおり。

## 試し方

1. ブラウザの拡張機能管理画面で、この拡張機能を再読み込みする。
2. 開いている法令タブも再読み込みする。
3. 自動有効化をOFFにして法令を開く。本文表示後、引用元情報だけを非同期で取得・保存する。条文への逆リンク付与は行わない。
4. 逆リンクを有効にする。先読み済みなら保存結果を使って付与する。先読み中なら同じ取得を待つ。
5. 同じ法令を再読み込みし逆リンクを有効にすると、法令キャッシュが有効な間は逆リンクも保存済みデータを使用する。
6. 「法令ファイルの再取得」で法令を更新すると、その法令ファイルに紐づく逆リンクキャッシュを直ちに削除し、OFFでも新しい情報を非同期で取得・保存する。

自動有効化ONの場合は、法令本文を読み込み表示した後、非同期で取得する。通常画面ではページが取得済みの目次・改正版情報を利用できれば引用元APIの1通信のみ。目次がない場合は追加取得する。軽量表示は公開APIの改正IDを内部APIのIDに対応付けるため、初回は履歴・目次・引用元の3通信。

## 保存と更新

逆リンクOFF時の先読みでも、取得開始からキャッシュ保存処理の完了まで右下に通知を表示する。設定処理と先読みが重なっても、両方が終わるまで通知を消さない。保存無効設定や保存失敗の場合は「キャッシュ未保存」と表示し、保存済みとは案内しない。取得失敗時は失敗通知に切り替える。

先読み・キャッシュ保存中は逆リンクボタンを無効化し、Eキーによる切り替えも受け付けない。保存完了後に操作可能へ戻す。失敗・未保存の場合も、再試行できるよう操作可能へ戻す。

- `egov-inyo-api-v1` という専用Cache Storageを使用し、法令キャッシュの容量計算には含めない。同梱・インポート済み逆リンクの既存IndexedDBは変更しない。
- 通常／軽量、法令、表示版・時点を区別。法令本文の取得日時が一致する場合だけ再利用する。法令を再取得すれば同じ改正版でも逆リンクは再取得する。
- 寿命は法令と同じ更新設定（毎日1日、毎週7日、毎月30日、手動は期限なし）。起点は逆リンク取得日時ではなく法令本文の取得日時。「毎回」では永続保存しない。
- 独立した更新ボタン・更新タイマーは実装しない。法令の読み込み後に先読みし、期限判定は先読み・逆リンク要求時に行う。期限を超えた法令タブを開いたまま使う場合、逆リンクの要求時にAPIを取得しても、期限切れ本文に紐づく結果は永続保存しない。法令の再取得後に通常の保存へ戻る。
- 専用保存領域は法令容量の上限による削除対象にも入らない。本文が容量都合で削除されても、次に本文を取得すると取得日時が変わるため古い逆リンクを再利用しない。同一表示の保存枠は新しい結果で置換する。
- 先読み失敗時は本文表示を妨げず、逆リンクON時に再試行する。ON時のAPI失敗は表示する。同梱JSONへのフォールバックはしない。
- API引用元は現在の条・項・号・附則のキーに変換する。章見出しだけに付いた引用は現在の表示形式では付与しない。同梱JSONとの引用件数の一致は保証しない。内部APIにない同梱の裁判所規則は外部引用元を取得できない。

## 検証結果

### 操作停止への対処

API通信は非同期だが、表示側の法令内参照解析・対象要素索引作成・参照結果の統合は一括実行で、DOM反映も最初の120〜160件を即時に実行していた。これらを分割し、約4msを目安にイベント処理へ制御を戻すよう変更した。DOM操作1回の所要時間まで4ms以内に保証するものではない。反映が実際に終わってから完了表示を出し、無効化や法令切り替えで古い処理を中断する。

Chromeで1,200条・3,600参照の試験データを解析した単独実行では、一括処理約69msの間は予約したクリック処理が0回だったのに対し、分割処理約161msの間にクリック処理33回、描画9回が進んだ。解析・統合結果の一致と中断も確認。総処理時間の最短化ではなく操作応答性を優先する変更。ユーザーが停止を経験した実際の法令・端末条件での再現測定ではない。

この変更後の全テスト：129件成功、任意の旧版比較1件スキップ。API試用前への完全復元は既存の復元スクリプトで引き続き可能。

- 既存を含む全テスト：125件成功、任意の旧版比較1件スキップ。その後追加した軽量表示の手動／自動有効化2件もChromeで成功。
- 通常画面：本文の表示前には引用元を取得せず、表示後はOFFでも先読み。既存メタデータから1通信、ページ再読み込み後の永続キャッシュ利用、本文再取得日時変更による失効をChromeで確認。
- 軽量表示：実際のviewerを読み込み、本文取得を遅延させても逆リンクを先に取得しないこと、本文表示後の手動ON／自動ONでAPI結果が条文へ付与されることをChromeで確認。
- 実APIで独占禁止法を取得：通常用は1通信約895ms、キャッシュヒット0通信約0.5ms、軽量用は3通信約2,075ms。いずれも53対象キー・164引用元。これは今回の接続条件での取得処理のみの単発測定。
- 復元スクリプトを別の作業用フォルダへ実行し、7ファイルが基点コミットのチェックアウト内容とバイト単位で一致することを確認。

### 先読みと再取得時削除の追加検証

通常・LiteのOFF時先読み、ON時の再利用、先読みとON要求の通信一本化、再取得直後の物理削除、先読み失敗後の再試行、削除前に開始した取得の完了による古いキャッシュ復活の防止を検証。キャッシュは引き続きモード・表示ごとに分離し、法令の容量上限には加算しない。

## 整理候補として残したもの

### 優先度：中 — 旧インポート／試用切り替え経路

`background.js` の getImportedLawReferences / readCachedLawReferences / saveBundledCacheRecord と、オプションの逆リンクJSON読み込み処理は残っている。既定のREVERSE_REFERENCE_SOURCE='api'では、読み込み済みJSONは逆リンク表示に使わない。書き出し用の保存データと旧取得経路として維持されている。

今後は「旧機能を正式に終了して保存・書き出しだけ残す」か「API結果に手動データを重ねる機能として残す」かを先に決めたい。今回は保存済みデータや機能を勝手に削除せず、画面の説明だけを実態に合わせた。全法令版への完全復元はバックアップから行う旨のコードコメントも修正した。

### 優先度：中 — オフライン検索の全キー走査と排他制御

オフライン本文の候補検索は依然として通常キャッシュの全キーを走査する。今回、過去本文をすべて文字列化する処理は除いたが、キーごとのCache Storage参照は残る。また、読み取りはwithLawCache内なので、検索中は他の法令キャッシュ操作が待つ。

多数の法令を保存した環境で待ち時間を測り、問題があれば読み取り時の排他範囲短縮や索引を検討する。索引の追加には保存・削除・容量超過時の同期処理が増えるため、現段階で新しい保存層は追加しなかった。

### 優先度：低 — 通常／Liteのブックマーク正規化など

`content.js` と `viewer.js` には normalizeArticleBookmarks、getArticleBookmarks、getReferenceLinkModeText の完全一致部分がある。normalizeArticleBookmarkも、ローカル変数名を除くと実質同じ。

正規化のような純粋な処理は共通化の候補。getArticleBookmarksはそれぞれの画面内の読み込み状態を参照するので、全文を機械的に共有モジュールへ移すだけでは整理にならない。全体のサイズに対して重複部分は小さく、今回は画面固有の状態管理を変えなかった。

### 優先度：低 — 停止中のGoogle Drive同期

GOOGLE_DRIVE_SYNC_AVAILABLE=falseだが、background.jsに同期用の定数・関数群が残っている。条件付きで呼ばれないことと、不要なコードがないことは別なので、将来復活させないと決めた場合は分離・削除する価値がある。現在の主な負担は配布量・初期解析・保守であり、同期が常時実行されているとは判断していない。

### 優先度：低 — 大きな画面スクリプト

content.jsとviewer.jsは大きいが、e-GovのDOMを扱う通常版とXMLから描画するLite版には実際の差がある。ファイルの大きさだけを理由に同じ抽象化へまとめることは勧めない。ブックマーク、トースト、参照一覧など、独立して検証できる機能から分割する方が安全。

## 維持した設計

- API取得・変換はバックグラウンド側で実行し、画面への反映と内部参照解析は分割してイベント処理へ制御を戻す。
- 同梱逆リンクは小さなID一覧で対象を絞り、該当する法令だけ索引本文を利用する。
- キャッシュヒット時に法令本文を再ダウンロードしない。LRU記録の書き込みも毎回は行わない。
- 検索の進行中要求の共有・取り消し・古い結果の破棄、メモ復元の候補絞り込み、XML内の補則等の索引再利用は既存テストで維持を確認。
- 法令の通常キャッシュとLiteキャッシュ、API逆リンクと同梱索引は目的・寿命が異なるため、保存層を一つに統合しない。
